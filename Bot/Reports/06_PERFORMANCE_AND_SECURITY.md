## ⚡ تحليل الأداء واختناقات المعالجة (Performance Bottlenecks)

### 1. شلل الخيط الرئيسي بسبب الفحص الدلالي (`SemanticIndex` Blocking)
- **الموقع:** `dev/automation/semanticIndex.js` و `dev/automation/contentEngine.js`.
- **السبب الجذري:** 
  - عند فحص تشابه التغريدات المقترحة مع الأرشيف التاريخي، يقوم الفهرس الدلالي بحسابات معقدة تشمل: تقطيع الكلمات، إزالة التشكيل، حساب الأوزان العكسية `IDF`، ومقارنة المصفوفات عبر خوارزمية Jaccard لآلاف النصوص السابقة.
  - تجري هذه العمليات بشكل **متزامن (Synchronous CPU-bound)** على خيط الأحداث الرئيسي (Node.js/Electron Main Event Loop).
- **الأثر العملي:**
  - تجميد كامل لواجهة تطبيق Electron أثناء توليد الدفعات الكبيرة (Batch Generation).
  - تأخر الاستجابة لرسائل IPC وأحداث واجهة المستخدم لعدة ثوانٍ عند وصول الأرشيف إلى 10,000+ تغريدة.

### 2. التضخم المتكرر في قراءة وكتابة SQLite (Write Amplification)
- **الموقع:** `Bot/src/sqliteStore.js`.
- **السبب الجذري:** 
  - حفظ شجرة بيانات البوت بالكامل ككتلة JSON واحدة في جدول أحادي السطر.
  - تنفيذ `JSON.parse` و `structuredClone` و `JSON.stringify` عند كل تحديث لحالة عنصر في الطابور أو تغيير مؤشر زمني.
- **الأثر العملي:**
  - استهلاك مفرط لدورات المعالج (CPU cycles) في معالجة السلاسل النصية الطويلة.
  - توليد عمليات إدخال/إخراج كثيفة على القرص (I/O Bottleneck) وتضخم ملف WAL، مما يرفع زمن استجابة استعلامات قاعدة البيانات إلى مئات المللي ثانية في الحالات الحرجة.

### 3. تراكم المستمعين وتسريب الذاكرة (Memory Leak & Listener Accumulation)
- **الموقع:** `Bot/src/directX.js:68-75` و `Bot/src/telegramApi.js`.
- **السبب الجذري:**
  - عند فتح جلسات متعددة أو إعادة محاولة الاتصال، يتم ربط دوال استماع للأحداث (`child.stdout.on`, `child.stderr.on`, `child.on('exit')`) دون إزالتها الصريحة عند إغلاق أو فشل الجلسات السريعة.
  - يؤدي ذلك إلى تحذيرات Node.js الشهيرة: `MaxListenersExceededWarning: Possible EventEmitter memory leak detected`.
  - نمو تدريجي في استهلاك الذاكرة العشوائية (RAM) في العمليات التي تعمل لأيام متواصلة.

### 4. مخاطر فيضان مخزن العمليات الفرعية (Subprocess Stdio Buffer Overflow)
- **الموقع:** `Bot/src/directX.js`.
- **السبب الجذري:**
  - يعتمد الاتصال بين Node.js وبايثون على أنابيب `stdio` القياسية (`pipe`).
  - في حال صدور مخرجات ضخمة غير متوقعة أو تجميد القراءة، يمتلئ مخزن الأنبوب المؤقت (عادة 64 كيلوبايت في أنظمة لينكس)، مما يؤدي إلى تعليق العملية الفرعية (Deadlock).
  - يقوم الكود الحالي بإنهاء العملية بالقوة عبر `SIGKILL` عند انتهاء المهلة دون محاولة إفراغ التدفق (Graceful Drain).

## 🔍 التفاصيل الفنية للثغرات الحرجة

### 1. تسريب عنوان IP الخادم الحقيقي (`src/dockerVpn.js:77-83`)
```javascript
  async function getServerIp() {
    try {
      const { stdout } = await command('curl', ['--noproxy', '*', '--ipv4', '--fail', '--max-time', '5',
        '--silent', 'https://api.ipify.org'], { timeout: 7_000 });
      const ip = stdout.trim(); return isPublicIp(ip) ? ip : null;
    } catch { return null; }
  }
```
- استخدام `--noproxy '*'` يوجه الاتصال عمداً خارج نفق VPN المشفر، مما يعرض خادم البوت للرصد، ويسجل عنوان IP الحقيقي لدى خوادم طرف ثالث (`ipify.org`).

### 2. خطر بقاء عمليات بايثون يتيمة (Orphaned Subprocess Risk)
- أثبتت الاختبارات المعزولة (`C_ACCEPTED` و `R_ACCEPTED`) أنه عند إيقاف عملية Node.js الرئيسية بالقوة (`SIGKILL`)، تظل عملية بايثون الفرعية `direct_x_bridge.py` قيد التشغيل وتتصل بشبكة X بشكل مستقل، دون إشراف أو قدرة على استقبال إشارات الإلغاء، ما قد يتسبب في إرسال تغريدات بعد أن ظن المشرف أنه أوقف النظام.

### 3. غياب الحماية عند أخطاء مؤقتات الجدولة (`src/scheduling.js`)
- استدعاءات `setTimeout` و `setInterval` في مهام الجدولة تفتقر إلى كتل `try/catch` عليا تحمي حلقة الأحداث. أي استثناء غير معالج داخل دالة المؤقت يطلق حدث `uncaughtException` ويؤدي إلى انهيار العملية بالكامل.

## 🛡️ الإجراءات الوقائية المطلوبة في مرحلة الإصلاح
1. **عزل الحسابات الحساسة بالتشفير:** تشفير مجلد `data/cookies/` باستخدام مفاتيح مشتقة من مسار النظام الآمن `/run/secrets/`.
2. **نقل المعالجة الدلالية إلى Worker Thread:** تشغيل `semanticIndex.js` في خيط منفصل لتفريغ خيط الأحداث الرئيسي من أي حسابات ثقيلة.
3. **ضبط حراس الجلسات الفرعية (Subprocess Lifespan):** استخدام مجموعات العمليات (`process groups / setpgrp`) وضمان ارتباط عمر العملية الفرعية بعمر العملية الأم عبر أنابيب الاتصال القياسية أو `prctl(PR_SET_PDEATHSIG, SIGTERM)`.
4. **تثبيت مكتبة SQLite مستقرة أو ترقية نمط الاستخدام:** تثبيت الحزم الإنتاجية المعتمدة والتأكد من توافق إصدار Node.js مع بيئة الإنتاج.
