## 🏛️ النظرة الهيكلية العامة
مشروع **YJAutoPostOnX** مبني على بنية متعددة اللغات (Polyglot Architecture) تفصل بين واجهة المستخدم وإدارة الحالة (Node.js) وبين هندسة الاتصال المعكوسة بمنصة X وتخطي بصمات المتصفح (Python 3.12)، مدعومة بمستوى عزل شبكي محلي (Docker Containers) لتأمين مسارات الخروج عبر بروكسيات مشفرة.

## 📂 المكونات البرمجية والمسؤوليات التفصيلية

### 1. طبقة البوت والتشغيل الخلفي (`Bot/src/`)

- **`src/index.js` (نقطة الدخول والتمهيد):**
  - مسؤول عن تهيئة النظام، والتحقق من المعلمات البيئية، وفتح مستودع البيانات `sqliteStore`.
  - إدارة إشارات إيقاف النظام (`SIGINT`، `SIGTERM`)، والإغلاق المنظم لكافة العمليات الفرعية والاتصالات.
  - إطلاق البوت، ومراقب الخمول `watchdog`، وجدولة مهام `runner`.

- **`src/runner.js` (محرك إدارة دورات النشر):**
  - ينظم دورة حياة المنشور من طابور الانتظار وحتى النشر النهائي.
  - يحتوي على دالة حجز العنصر الذرية `claimCycleItem`، وحساب الكوتا اليومية بتوقيت الرياض (`riyadhDay`).
  - تطبيق فترات التهدئة العشوائية (`delayMinSeconds` إلى `delayMaxSeconds`).
  - معالجة حالات الاستجابة: `published`، `ambiguous`، `pending`، `cancelled`.

- **`src/directX.js` (محول الاتصال المعزول بـ Node.js):**
  - يدير العمليات الفرعية لبايثون (`child_process.spawn`) باستخدام وسائط معزولة (`python3 -I -u`).
  - ينفذ بروتوكول اتصال مبني على الأسطر النصية عبر `stdin/stdout` دون تمرير أي بيانات حساسة أو نصوص استثناءات في سجلات الخطأ القياسية.
  - يوفر مصافحة النشر الذرية (`onDispatch`) لضمان عدم بدء إرسال HTTP قبل تسجيل مرحلة الدخول في قاعدة البيانات.

- **`src/sqliteStore.js` (مستودع الحالة وقاعدة البيانات):**
  - يعتمد على موديول Node.js المدمج `node:sqlite` عبر صنف `DatabaseSync`.
  - يضبط محرك SQLite بقواعد صارمة: `PRAGMA busy_timeout=30000; PRAGMA journal_mode=WAL; PRAGMA synchronous=FULL;`.
  - يضمن قفل المسار وتعديل أذونات الملفات إلى `0600` وحصر الدليل بـ `0700`.

- **`src/accounts.js` و `src/accountTable.js` (إدارة الحسابات والكوكيز):**
  - قراءة وفحص ملفات الكوكيز المدعومة بصيغ متعددة (JSON، Netscape، Text).
  - تصنيف حالات الحسابات (`مفعل`، `محظور`، `كابتشا`، `غير مفعل`).
  - استيراد وتحديث الحسابات جماعياً عبر واجهة CSV مع فحص صحة المدخلات.

- **`src/dockerVpn.js` و `src/publicIp.js` (إدارة شبكة البروكسي):**
  - إدارة دورة حياة 5 حاويات Docker تعمل كبروكسيات محلية SOCKS5h على المنافذ `18801` إلى `18805`.
  - فحص سلامة الحاويات والتحقق من تطابق العقد (`contract=independent-v1`) وصورة النظام (`yj_autopost_vpn_image:latest`).
  - جلب عنوان IP الخارجي لكل منفذ عبر استعلام محلي موجه للبروكسي.

- **`src/telegramApi.js`، `src/telegramUi.js`، `src/telegramFlows.js` (واجهة تيليجرام):**
  - بناء واجهة تفاعلية كاملة مع أزرار Inline ولوحات التحكم.
  - دعم تدفقات إضافة وتعديل الحسابات، وجدولة النشر، وعرض الطابور، والتحكم بالكوتا.

- **`src/watchdog.js` (مراقب التعليق والخمول):**
  - يعمل في خيط مستقل (`Worker Thread`) لفصل مراقبة النبض عن حلقة الأحداث الرئيسية (Event Loop).
  - يكتشف حالات تجمد حلقة الأحداث أو توقف استطلاع تيليجرام (`eventLoopStalled` / `pollingStalled`) ويرسل تنبيهات تشخيصية.

### 2. طبقة النقل وجسر بايثون (`Bot/python/`)

- **`python/direct_x_bridge.py`:**
  - ينفذ خادم أوامر عبر سطر الأوامر القياسي (JSON IPC Bridge) في حلقة `asyncio`.
  - يتولى تهيئة جلسة X (`DirectSession`) عبر مكتبة Twikit المهيأة.
  - يحتوي على `OnlySocksTransport` الذي يوظف `curl_cffi` لمحاكاة بصمة متصفح Chrome TLS/JA3 وتفادي حظر Cloudflare و X Bot Detection.
  - يحتوي على دالة التحقق الجنائي من التايملاين `verify_timeline` للتأكد من وصول التغريدة إلى صفحة الحساب.

- **`python/direct_x_compat.py`:**
  - طبقة توافقية تعزل تعديلات Twikit دون التعديل العام على كود المكتبات (No Monkey Patching).
  - يوفر فئات مخصصة لمعالجة غياب خصائص المستخدمين (`_compat_user_data` لتفادي `KeyError: 'urls'`).
  - يحتوي على دالة تصنيف أخطاء الحسابات `classify_x_account_failure` لفرز الحظر والكابتشا وأخطاء المصادقة.

---

### 3. طبقة محرك المحتوى والأتمتة المكتبية (`dev/`)

- **`dev/automation/contentEngine.js`:**
  - محرك توليد تغريدات العملات الرقمية باللغة العربية بجودة عالية.
  - يدير مصفوفة زوايا الطرح (`ANGLE_MATRIX`) التي تحتوي على أكثر من 30 زاوية متخصصة (سيكولوجيا التداول، إدارة المخاطر، التحليل الفني، الشموع اليابانية، معدلات التمويل).
  - يفرض ميزانية صارمة لعدد الحروف: 170 إلى 270 حرفاً تشمل رابط الإحالة ووسوم الهاشتاغ.
  - يمنع التكرار اللفظي الداخلي وتوليد الكلمات المتطابقة المتعاقبة.

- **`dev/automation/semanticIndex.js`:**
  - محرك فحص دلالي للتشابه في المعنى وليس فقط تطابق الحروف.
  - يتضمن معالجة متقدمة للنصوص العربية (إزالة التشكيل، التطويل، توحيد الألفات والياء والتاء المربوطة، وتصفية قائمة الكلمات الوظيفية STOPWORDS).
  - يوظف الفهرس المعكوس (Inverted Index) مع أوزان `IDF` (Inverse Document Frequency) ومقياس Jaccard الدلالي للتحقق من عدم تكرار الأفكار السابقة عبر مئات الآلاف من التغريدات.

- **`dev/automation/durableQueue.js` و `dev/automation/workflowStore.js`:**
  - إدارة طابور النشر وجدولة التوليد وحفظ تدفق العمل في تطبيق Electron المكتبي.

## 🔄 مسار تنفيذ دورة النشر الكاملة (End-to-End Execution Flow)

يوضح المخطط التالي المسار البرمجي الدقيق منذ لحظة استحقاق موعد النشر وحتى تأكيد النجاح:

```
[1. جدولة أو استحقاق النشر]
        │
        ▼
[2. runner.js: launchCycle()]
        │
        ├─► فحص اتصال الإنترنت والمكونات
        ├─► قراءة قاعدة البيانات: bot.store.load()
        ▼
[3. حجز العنصر: claimCycleItem()]
        │
        ├─► اختيار المنشور التالي في حالة 'pending'
        ├─► اختيار حساب مفعل يمتلك رصيد كوتا متاح
        ├─► توليد رمز محاولة فريد: attempt.token (UUIDv4)
        ├─► تحديث حالة المنشور إلى 'processing' داخل معاملة ذرية
        ▼
[4. تهيئة جلسة النشر: directX.open()]
        │
        ├─► تخصيص منفذ البروكسي (مثال: socks5h://127.0.0.1:18801)
        ├─► إطلاق / الاتصال بعملية بايثون الفرعية
        ├─► إرسال أمر {'op': 'open', 'account': {...}, 'proxy': ...}
        ├─► فحص الهوية والتحقق من عدم حظر الحساب
        ▼
[5. بدء النشر: directX.publish()]
        │
        ├─► استدعاء مصافحة النشر: onDispatch()
        │        │
        │        ▼
        │   [تحديث SQLite: حالة العنصر تصبح 'dispatching']
        │
        ├─► إرسال أمر النشر إلى بايثون: {'op': 'publish', 'text': ...}
        │        │
        │        ▼
        │   [direct_x_bridge: إرسال HTTP POST عبر curl_cffi إلى X]
        │        │
        │        ├─► إذا نجح: استلام رد GraphQL برقم التغريدة (tweetId)
        │        │
        │        └─► إذا فشل أو انقطع الاتصال:
        │                 │
        │                 ▼
        │            [تنفيذ فحص التايملاين: verify_timeline]
        │                 │
        │                 ├─► وُجدت التغريدة: استرجاع الحالة كنشر مؤكد
        │                 └─► لم تُوجد: إرجاع نتيجة غامضة أو غير منشورة
        ▼
[6. معالجة النتيجة: runner.js - store.update()]
        │
        ├─► في حالة النجاح المؤكد ('published'):
        │        ├─► تحديث حالة المنشور إلى 'published' وتسجيل الرابط
        │        ├─► زيادة كوتا الحساب اليومية في جدول اليوم
        │        ├─► جدولة المنشور القادم بتأخير عشوائي آمن (nextPostAt)
        │        ├─► إرسال إشعار تيليجرام للمشرف
        │        └─► تسجيل الحدث في سجل الفحص الجنائي forensicLogger
        │
        └─► في حالة عدم التأكد أو الغموض:
                 ├─► عزل المنشور إلى حالة 'ambiguous' (لمنع التكرار)
                 ├─► عدم استهلاك الكوتا
                 └─► إرسال تنبيه فوري للمشرف بالمراجعة اليدوية
```

## 🔌 مصفوفة واجهات التفاعل والبروتوكولات (Protocols & Interfaces)

| المسار | نوع الاتصال | البروتوكول والبيانات | مهلة الانتظار (Timeout) |
|---|---|---|---|
| **Telegram -> Bot** | شبكي صادر | HTTPS Long-Polling (`getUpdates`) | 50 ثانية (طلب)، 60 ثانية (مقبس) |
| **Bot -> SQLite** | محلي في نفس العملية | `node:sqlite` DatabaseSync عبر WAL | 30 ثانية (`busy_timeout`) |
| **Node.js -> Python** | IPC محلي عبر معالج فرعي | JSON-Lines عبر `stdin`/`stdout` | 30 ثانية (فتح)، 45 ثانية (نشر) |
| **Python -> Docker VPN** | شبكي محلي Loopback | SOCKS5h عبر TCP Ports `18801-18805` | 10 ثوانٍ لكل محاولة اتصال |
| **Docker VPN -> X** | إنترنت خارجي مشفر | HTTPS عبر بروتوكول WireGuard / OpenVPN | 15-30 ثانية لطلبات GraphQL |
| **Watchdog -> Bot** | IPC داخلي (Worker) | رسائل Node Worker MessagePort | نبض كل 5 ثوانٍ، إنذار عند 180 ثانية |
